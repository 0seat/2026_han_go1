# 계약 — 합의 없이 바꾸면 안 되는 것

여기 있는 것은 **둘 이상이 걸려 있어서 어느 파일도 혼자 소유할 수 없는** 것들이다.
한 사람 안에서 끝나는 것은 여기 없다. HLC 관측을 몇 차원으로 할지, 은닉층을
몇으로 할지, 보상을 어떻게 줄지는 아무도 안 물어본다.

숫자는 여기 적지 않는다. **어느 파일이 소유하는지만 적는다.** 숫자를 두 곳에
적으면 어긋나고, 어긋나도 크기는 같아서 아무도 모른 채 학습이 망한다.
지난번 LLC와 HLC 입력 차원이 안 맞아 재학습한 사고가 그것이었다.

---

## C1  경로 형식 — nav 와 HLC

nav가 낸 것을 `common/path.py`의 `encode`에 넣고, HLC는 그 함수가 낸 것을 받는다.
**양쪽 다 이 함수를 부른다.** 각자 변환을 만들면 안 된다.

```
소유    go1_nav/common/path.py
크기    path.SIZE      <- 이 값을 읽어 쓴다. 숫자를 옮겨 적지 말 것
```

여기서 나오는 제약 둘. **물릴 수 없다.**

**경로 점 개수는 고정이다.** `encode`가 `jit` 안에서 도는데 배열 크기가
바뀌면 매번 다시 컴파일된다. nav는 점 개수를 정해두고 모자라면 마지막 점을
반복해 채운다.

**학습 중에는 nav를 부를 수 없다.** D*는 `jit` 안에 못 들어간다. 경로는 이미
만들어진 채로 상태에 들어와 있어야 한다.

바꾸려면: nav 담당 + HLC 담당 합의, PR.

---

## C2  명령 형식 — HLC 와 LLC

HLC는 **학습된 축의 값만** 낸다. 나머지는 부르는 쪽이 기준값으로 채운다.

```
소유    go1_nav/llc/spec.py
        COMMAND_ORDER    11축의 순서
        TRAINED_DIMS     지금 살아있는 축
        BASE_VECTOR      전체 기본값
        TRAINED_INDEX    학습축이 11칸 중 몇 번째인가
        RANGES           명령 범위
        TRACKING         실측 (이득, 편향, R^2)
```

`jit` 안에서 조립하는 한 줄.

```python
command = jnp.asarray(spec.BASE_VECTOR).at[jnp.asarray(spec.TRAINED_INDEX)].set(action)
```

**미학습 축을 HLC 액션에 열지 않는다.** 응답이 없는 축을 탐색하느라 표본을
낭비한다. 열려면 LLC를 먼저 재학습해야 한다.

새 LLC가 축을 열면 `TRAINED_DIMS`에 이름이 늘고 **HLC의 액션 크기가 따라
늘어난다.** 그래서 HLC는 `len(spec.TRAINED_DIMS)`를 읽어 쓴다.

바꾸려면: LLC 담당이 실측으로 확정한 뒤 PR. 추측으로 고치지 않는다.

---

## C3  시뮬레이션 조건 — 전원

정책을 바꿔 끼우려면 같은 조건에서 학습돼야 한다. 다르면 조용히 이상해진다.

```
소유    체크포인트 자신 + go1_nav/hlc/env.py
읽기    loader.inspect(체크포인트)   관측 · 액션 · 은닉층 크기
        env.dt                       제어 주기
```

**이 숫자들을 코드에 적지 않는다.** 관측 크기는 env가 내고 가중치는
체크포인트가 내며, 둘이 다르면 첫 행렬곱에서 죽는다. `loop.py` 어디에도
56도 12도 11도 없다.

새 정책을 받으면 `hlc/env.py`의 `gate()`를 한 번 돌린다. 8줄 구조 검사다.
차원 검사가 아니라 **가설 검사**다 -- 명령이 정말 관측 꼬리에 실리는지를
슬롯을 흔들어 직접 확인한다. 여기서 걸리면 "슬롯이 죽었다"와 "자리를 잘못
짚었다"를 구별할 수 없다.

## C4  더미 교체 — 전원

`stub.py`의 함수 이름과 입출력은 계약이다. 안은 자유다.

```
nav   def path(world, robot_xy, goal_xy) -> (N, 2)
HLC   def act(features) -> (len(spec.TRAINED_DIMS),)
```

바꾼 뒤 `loop.run`을 돌려 세 줄을 확인한다. 안 넘어진다 · 앞으로 간다 ·
영상에서 걷는다. **학습을 시작하기 전에 돌린다.** 그래야 어긋난 날 안다.

## C5  미로 형식 — HLC 와 nav

미로는 `hlc/maze.py`가 만든다. nav는 아직 import 하지 않지만, D*를 짜는 날
**`blocked`와 `level`과 `kind`를 읽고 같은 통과 규칙을 써야 한다.**

```
소유    go1_nav/hlc/maze.py
        CELL, TILE, SPAN, DEPTH   눈금.  npz에 같이 저장되고 읽을 때 대조한다
        kind, level, axis         랜드 표
        blocked                   랜드 단위 점유 격자
        reachable(), route()      통과 규칙
```

**통과 규칙을 두 번 적지 않는다.** nav의 D*는 `_can_move`와 같은 판정을 써야
한다. 두 벌이 되면 "경로는 나왔는데 못 간다"가 되고, 그것은 정책의 잘못으로
보인다.

```
막힌 랜드        못 간다                       벽 · 도랑 · 절벽
둘 다 경사       같은 축이면 간다
한쪽만 경사      그 경사의 축을 따라갈 때만
높이가 같다      간다
높이가 다르다    내려가는 쪽만                 <- 단방향 간선
다리 · 터널      제 통로 방향으로만
```

`blocked`만으로는 단방향을 표현할 수 없다. `level`을 같이 읽어야 한다.

**`path`도 `route()`도 학습 신호로 쓰지 않는다.** 앞은 생성기가 판 자국이고
뒤는 랜드 개수 기준 최단이다. 지나갈 수 있는 길은 여럿이고 정책이 어느 것을
고르든 틀린 게 아니다. 실측 200개에서 최단 경로가 판 자국을 벗어난 미로가
190개였다.

바꾸려면: HLC 담당 + nav 담당 합의, PR. `maze.py`를 `common/`으로 옮기는 날
이 항목이 그대로 따라간다.
