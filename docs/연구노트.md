# 연구노트 — HLC 1단계

Go1 계층 제어기의 상위 정책(HLC)을 학습시킨 기록이다. **무엇을 쟀고 무엇이
틀렸는지**를 남긴다. 성공한 설정만 적으면 다음 사람이 같은 벽에 다시 부딪힌다.

새 작업은 맨 아래 `진행 중` 절에 이어 붙인다.

---

## 1. 구조 요약

```
 nav (미구현)  ->  HLC (여기)  ->  LLC (phase18, 동결)  ->  Go1 12관절
```

**관측** 255개. 서명 `4f5aa2e2400160b7`.

```
 자기상태 x 쌓기   linvel 3 + gyro 3 + gravity 3 + 지면높이 1 + 명령 11 = 21, x 3
 지형 스캔         91  (앞뒤 · 좌우 격자, 지면 기준)
 천장 스캔         91  (몸통 원점 기준. 숙일지 말지)
 길잡이            10  (경유점 3 x [방향x, 방향y, 압축거리] + 목표 직선거리)
```

**행동** 11축 명령 중 6축만 연다. 나머지는 `UNTRAINED_HOLD` 고정.

```
 열림   vx, vy, yaw, height, pitch, roll
 닫힘   stance_width, step_freq, gait_phase, gait_duration, footswing
```

**보상**

```python
reward = ( 1.0  * progress          # 경로를 따라 남은 거리가 줄어든 양, ±0.5 로 자름
         + 10.0 * reached           # 목표까지 직선거리 < 0.5 m
         - 10.0 * fell
         - 0.005                    # 스텝마다. 200 스텝 다 쓰면 -1.0
         - 0.02 * sum|명령 변화| )
```

**에피소드** 200 HLC 스텝 = LLC 1000 스텝 = 20.0 초.

## 3. 지형 상수를 실측으로 정한 것

### 터널 천장 `TUNNEL_CLEAR = 0.32`

모델의 몸통 geom 오프셋(0.2359 m)은 못 쓴다. 그 값을 믿으면 0.36 터널을 못
지나야 하는데 실제로는 지난다. 통과 여부를 직접 쓸어서 정했다.

```
 천장    명령 0.30 (기본)      명령 0.25 (최저)
 0.36    통과                  통과
 0.34    실패                  통과
 0.32    실패                  통과      <- 여기
 0.30    실패                  실패
```

0.32는 **숙여야만 지나는** 가장 높은 격자점이다.

### 다리 폭 `BRIDGE_WIDTH = 0.60`

예전 값 0.40은 stance width 0.202 m의 두 배라는 것 말고 근거가 없었다.

```
 폭     고정 (직진만)   조준 (조향한다)
 0.40   0.062           0.062
 0.60   0.312           0.375      <- 여기
 1.00   0.438           0.688
```

0.40은 조향해도 0.062다. 폭이 아니라 발 놓는 정밀도의 문제고, HLC는 속도만
명령하므로 학습으로 메울 여지가 얇다.

### 경사 `SLOPE_DEG = 20.0`

주석의 "Go1 등판 한계 25도"는 **실기 사양이지 이 체크포인트의 값이 아니다.**
고정 명령으로는 2 m 경사의 0.3~0.4 m까지만 오른다. 학습하면 오른다(4절 참고).

## 4. 학습 기록

도달률의 자가 두 종류다. **섞어 읽지 말 것.**

```
 학습 로그    brax 평가. `deterministic_eval`이 꺼져 있으면 확률적 행동
 결정적 측정  train.policy(deterministic=True) + baseline.evaluate
```

그리고 `14` 이전의 모든 학습은 **에피소드가 100 스텝에서 잘린 상태**였다
(6절 참고). 판끼리의 비교는 조건이 같아 유효하다.


### 차선 복도 — 망각을 막은 구조

랜드를 하나씩 이어 학습하면 **마지막 판만 남는다.** 실측이 잔인하다.

```
 다리 학습 뒤 터널 재측정   0.875 -> 0.000
   넘어짐 0.000, 시간초과 1.000.  입구 앞에 서 있었다
```

한 배치의 모든 환경이 같은 hfield와 같은 천장 geom 목록을 쓴다. 천장 개수가
컴파일 시점에 굳으므로 배치에 판을 섞을 수 없다. 그래서 **한 지형에 차선을
나란히** 두고 에피소드마다 차선을 뽑는다(`lands.mixed_corridor`).

효과는 잊지 않는 정도가 아니었다.

```
 터널   단독 학습 0.875  ->  차선 복도 0.969
 다리   단독 학습 0.805  ->  차선 복도 0.781  (오차 안)
 평지   학습 차선에 없는데 1.000  (거침이 대신 지켰다)
```

### 경사 — 커리큘럼이 필요했다

경사 단일 복도는 커리큘럼 없이는 안 붙는다. 도달이 10M 내내 0.000이고
로봇은 **경사 앞 x 1.0에 서 있다.**

```
 가만히 서 있기       -1.0   (TIME_COST x 200)
 경사 앞까지 걸어옴   +1.0   (전진 보상)
 합                   ~0     실측 -0.2
 시도하다 넘어짐      -10
```

도달 확률이 0이면 `GOAL_BONUS`는 기대값에 안 잡히고 `FALL_PENALTY`만 잡힌다.
시도의 기댓값이 늘 음수라 **정책이 옳게 계산한 것**이다.

`start_shift`로 경사 중턱에서 출발시켜 보너스를 잡게 하고, 뒤로 물렸다.

```
 밀기 2.6 -> 2.0 -> 1.4 -> 0.8 -> 0.0,  최종 0.898
```

**100 스텝 절단을 고친 뒤 커리큘럼 없이 다시 돌려도 0.000이었다**(15_경사재시도,
8판 중 7판이 200 스텝을 x 1.0 앞에서 소진). 커리큘럼은 실제로 필요했다.

### 꺾임 — 경로 보상이 필요했다

직선 복도에서는 길잡이 3점이 **전부 같은 방향**을 가리켰다. 경유점 자리가 한
번도 쓰인 적이 없다. 꺾인 복도를 만들자 문제가 드러났다.

직선거리 보상은 벽 쪽으로 사선을 그어도 오른다. 실측 궤적이 ㄱ자가 아니라
대각선이었다. 보상을 **경로를 따라 남은 거리**로 바꿨다.

```
 직선 보상 (11_꺾임차선)   0.688
 경로 보상 (13_경로보상)   0.938
```

같이 바꾼 것이 하나 더 있다 — `run_in` 1 -> 2로 장애물과 모서리를 2 m 떼었다.
1이면 넘는 것과 도는 것을 동시에 시킨다(돌이 직선 0.953에서 꺾임 0.281로
떨어졌다). **둘 중 무엇이 얼마나 기여했는지는 안 갈린다.**

## 6. 찾은 결함

### 에피소드가 상한의 절반에서 잘렸다

**가장 컸다.** `stage1.step`이 `info["steps"]`를 올리고 그 위의 `EpisodeWrapper`가
또 올렸다. 스텝마다 2씩 가서 **episode_length 200이 실제 100 스텝**이었다.

```
 같은 파라미터 · 같은 판 · 같은 상한 200

 날 것 Task 로 굴리면    도달 0.938,  109 스텝쯤에 done
 brax 래퍼 씌우면        도달 0.008,  에피소드 길이 199.7
```

`14` 이전 모든 학습이 이 조건이었다. 짧은 판(50 스텝대)에서는 안 드러나다가,
도달까지 109 스텝 걸리는 판에서 갈렸다. 우리 코드는 그 값을 **읽지도 않았다** —
쓰기만 하고 안 쓰는 값이 래퍼의 것과 이름이 겹친 것뿐이다.

고친 뒤 평가기가 0.922를 냈다. 로그와 측정이 같은 것을 말하게 됐다.

### 경유점이 통로 중심을 정확히 가리킨다

경로는 타일 중심을 잇고 통로도 타일 한가운데에 그려진다. 둘이 같은 중심에서
나온다.

```
 경로 기준 y 오프셋   -0.8   -0.5   -0.3    0.0   +0.3   +0.5   +0.8
 터널 (벽 높이)        0.42   0.42   0.00   0.00   0.00   0.42   0.42
 다리 (파인 깊이)     -1.00  -1.00   0.00   0.00   0.00  -1.00  -1.00
```

**경유점만 따라가면 정렬이 공짜다.** 지형 스캔을 볼 이유가 없다. 5절의 거울판
결과가 "경로를 읽는다"까지는 말해도 "지형을 보고 정렬한다"는 말하지 못하는
이유가 이것이다.

`ROUTE_JITTER = 0.2`를 넣어 에피소드마다 경유점을 경로 수직 방향으로 흔든다.
전진 보상은 정사영이라 **옆으로 벗어난 양이 애초에 안 들어간다** — 실측으로
직선 구간 한 스텝 전진량 차이가 0.5%였다.

### 꺾인 차선의 경사가 절벽이 됐다

단이 바뀌는 자리를 꺾임 뒤로 두어서, `_ramp`는 양 옆 이웃이 같은 단이라
아무것도 안 그리고 모서리에 0.713 m 절벽이 섰다. 단이 바뀌는 자리를 **경사
타일 자신**으로 옮겼다.

같은 자리에서 벽 높이도 틀렸다. 벽은 `단 x HIGH + 0.8`이라, 단 0인 벽이 단 1인
통로(0.713) 옆에 서면 **0.087 m만 남아 넘어간다.** 벽을 이웃 통로의 최대 단으로
올린다(`_raise_walls`).

### 그 밖

```
 route_polyline    로봇을 앞에 붙여 누적거리를 재서 뒤로 가는 구간이 섞였다
 lane_route        출발점이 빠져 첫 구간의 전진 보상이 0 이었다
 맵 바깥 테두리    맨 바깥 차선이 가장자리에 붙어 로봇이 걸어 나갔다
 mat_rgba          무늬가 있으면 안 먹는다. 색은 무늬 픽셀에 직접 넣어야 한다
```

## 7. 틀린 진단 기록

같은 실수를 반복하지 않기 위해 남긴다. **대부분 "고정 명령이 못 하는 것"을
"정책이 못 하는 것"으로 읽어서 생겼다.**

```
 "LLC 가 20도 경사를 못 오른다"
   고정 명령 40판으로 판정.  6축 밖을 안 써 봤다.  틀렸다

 "잠긴 축(footswing 등)을 열어야 한다"
   위 판정에 기댄 결론.  학습시키니 6축으로 올랐다.  틀렸다

 "경사에서 에피소드가 짧다"
   600 스텝을 줘도 x 0.95 에 서 있었다.  틀렸다
   (다만 100 스텝 절단은 별개로 실재했다)

 "deterministic_eval 이 로그를 망가뜨렸다"
   껐을 때도 같았다.  진짜 원인은 steps 충돌.  틀렸다

 "정책이 경로 옆으로 새서 도달을 못 한다"
   경로 이탈이 0.01~0.24 m 였다.  틀렸다

 "0.766 이니 세 차선이 다 풀렸다"
   돌이 0.281 이었다.  산수로 추정하면 안 된다

 "왼쪽으로만 돈다"
   거울판에서도 오른쪽으로 돌았다.  지나쳐서 맵 밖으로 나간 것.  틀렸다
```

**맞았던 것 둘.** 경사의 "시도하지 않는 것이 최적"은 절단을 고친 뒤 재시도로
확정됐다. 정규화 std 바닥(1e-6)이 상수 채널을 10^5로 만든 것은 정규화 통계를
직접 찍어서 잡았다.
